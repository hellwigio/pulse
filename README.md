# Pulse

API вопросов и ответов на Flask, SQLAlchemy и Pydantic. Python 3.14+, uv.

## Запуск

```bash
make install
make env
make db-upgrade
make dev
```

Настройки — в `.env` (пример: `.env.example`). По умолчанию используется SQLite.
Сервер разработки: `http://127.0.0.1:5000`. Другой порт: `make dev PORT=8000`.

## Команды

```bash
make run        # запуск без явного включения debug
make dev        # debug и автоперезагрузка
make check      # тесты и проверка типов
make clean      # удалить сборки и кеши
make help       # все команды
```

## Миграции

```bash
make db-migrate m="Описание" # создать миграцию после изменения моделей
make db-upgrade                    # применить миграции
make db-downgrade                  # откатить одну миграцию
make db-current                    # текущая версия базы
make db-check                      # проверить соответствие базы моделям
```

## API

Для `/questions`, `/answers` и `/categories` доступны:

- `GET /` — список, `GET /<id>` — одна запись (`200`).
- `POST /` — создание (`201`).
- `PUT /<id>` — обновление с передачей всех полей, `PATCH /<id>` — частичное обновление (`200`).
- `DELETE /<id>` — удаление (`204`, без тела ответа).

Пути указаны относительно соответствующего ресурса, например `GET /questions`.
Поля JSON для создания и PUT:

| Ресурс | Поля |
| --- | --- |
| questions | `text`: строка длиной 3–255 символов |
| answers | `is_agree`: boolean, `question_id`: положительный ID существующего вопроса |
| categories | `name`: строка длиной 1–255 символов, `question_id`: положительный ID существующего вопроса |

Пробелы по краям строк удаляются. Ответ содержит эти поля и `id`.
ID задаётся в URL при обновлении, а не в теле запроса. PATCH принимает любое
подмножество полей; пустой объект ничего не меняет. `null` и неизвестные поля
отклоняются (`422`). Некорректный JSON возвращает `400`, неверный Content-Type — `415`.
Ошибки возвращаются в JSON с ключом `error`; отсутствующие записи и вопросы — `404`.

Категория связана с вопросом через `Category.question_id`; API допускает одну
категорию на вопрос, повторная привязка возвращает `409`. Существующее поле
`Question.category_id` не используется текущей ORM-связью и не входит в API.
Вопрос с ответами или категорией удалить нельзя (`409`): сначала удалите связанные
записи или перенесите их на другой вопрос. Проверка одной категории на вопрос
выполняется приложением; ограничения уникальности в существующей БД нет.

Примеры запросов — в `kulala/*.http`.
